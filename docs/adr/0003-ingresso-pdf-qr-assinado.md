# Ingresso como PDF com QR de token

Seguindo o padrão do Mio-Festa-2026 (outro projeto de referência), o ingresso não é uma tela do app: é um PDF gerado por inscrição confirmada, com um QR code validado no check-in. O QR também é exibido na página de status pública do inscrito, já que este projeto — diferente do Mio-Festa-2026 — não tem tela autenticada de participante. Decidido para reaproveitar um fluxo de check-in já validado (evita reinventar geração de PDF e scanner) em vez de desenhar um mecanismo novo.

**Atualização:** a versão original (issue #10) assinava o token do QR com `django.core.signing` antes de codificá-lo, para evitar um "ID cru" adivinhável. Isso foi removido depois: `Inscricao.token` já é gerado com `secrets.token_urlsafe(24)` (imprevisível e único por si só), então assiná-lo não acrescentava segurança — só uma camada a mais para manter. O QR hoje codifica o `token` diretamente. Também foi adicionado um campo separado, `codigo_checkin` (6 caracteres, sem 0/O/1/I/L), só para o fallback de digitação manual no check-in — o `token` longo era impraticável de digitar de cabeça.
